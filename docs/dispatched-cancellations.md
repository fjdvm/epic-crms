# Cancelling after dispatch (#346)

This backend slice adds no screen. `requestDispatchedCancellation(orderId, reason)` requires Fulfilment and a working Staff or Manager Role. It stores a request through the storefront, creates a waiting Manager approval and alerts eligible Managers. The Order remains dispatched. Manager decisions are forwarded through a durable notice to the storefront, which retains approval/decline state and sends one decision email. The Customer can GET `/api/orders/:id/cancellation` to read only their own request and decline reason. The Customer may POST `{reason}` to `/api/orders/:id/cancellation`; the storefront authenticates the Customer and restricts requests to their own dispatched Order. Customer requests enter the same Manager queue through the existing authenticated Staff signal, reconnect sync, or a user opening the cancellation list. Repeated requests reuse the same Order request.

`loadDispatchedCancellations()` returns request state, stock outcome, refund method and proof reference for the backend consumer. The Manager approves or declines with `decideApproval("Fulfilment", requestId, decision, reason)`. A decline requires a reason and never changes the Order. After approval, only a Manager can call `settleDispatchedCancellation(orderId, requestId, "restock"|"write-off", proofForm?, options?)`. Staff and Admin cannot execute settlement. Ordinary Staff cancellation through `cancelOrder` still works through preparing.

Prepaid settlement uses the original GCash, Maya or bank-transfer method and exactly one confirmed Private image uploaded by the executing Manager in Fulfilment. CREOMS links it to the Order as `cancellation-refund-proof`; the storefront independently verifies the link, retention, image size and decoded bytes. After all approvals, linked proof becomes Permanent before IMS work so an interrupted settlement never loses its evidence. A retry resumes from the persisted proof rather than an expiring browser upload reference. `reconcileCancellationProof(orderId)` only promotes the recorded proof and never repeats a refund. COD accepts no proof and records no refund.

The settlement is valued on whole Order line selling prices, excluding Delivery fees, and snapshots the stored limit. One Manager-level approval is final at any amount; there is no CEO step. Any approval binds the Order, original cancellation request, payment method and stock outcome.

Ecommerce commits the settlement intent before calling IMS. It uses immutable Reservation/line keys for add-back, marks handled lines released, and never deducts a write-off twice. A lost or partial IMS response can only resume the same settlement. Existing failed-delivery disposition must agree. Settlement blocks delivery, rebooking and conflicting inspection. Orders missing packed IMS references require reconciliation. Successful cancellation queues a deduplicated `order.cancelled_after_dispatch` audit and Customer cancellation email; the request records `order.cancel_requested` and alerts Managers. No timer or automatic cancellation retry is introduced.
